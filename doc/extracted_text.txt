3.2.1 Authentication
3.2.1.1 Login
Step 1: Access the FDA System Login Page
The user (Admin, Authority, or Super Admin) navigates to the FDA System administration portal at the official URL:
 
fda-website.vercel.app
 .
The authentication page is displayed with a split-screen layout:
Left panel: A branded gradient panel (blue to cyan) displaying the FDA System logo (water-drop icon), the headline 'Flood Monitoring System', and two feature cards: 'Real-time' and 'Safe Route'.
Right panel: A centered login form area with the title 'Welcome Back' and a subtitle notice explaining this portal is for Admin, Authority, and Super Admin roles only.
Figure 32: Login – Login Page Overview
Step 2: Enter Email or Phone Number
The user enters their registered email address or phone number into the 'Email / Phone number' input field.
The user then clicks 'Continue' to proceed.
The system calls the identifier-check API to determine the appropriate authentication method for the account.
Figure 33: Login – Enter Identifier
Step 3.1: Login with Password
If the system determines the account uses password-based authentication, the form transitions to a password entry step:
A text line displays: “
Account
: &lt;user's email/phone&gt;”
A “
Password
” field appears with a lock icon on the left and a show/hide eye icon on the right.
A “
Forgot password?
” link appears next to the password label.
A “
Sign In
” → primary button and a “
Back
” secondary button are shown.
The user enters their password and clicks 'Sign In' to submit.
Figure 34: Login – Password Entry Form
Step 3.2: Login with OTP
If the system determines the account uses OTP-based authentication, the system automatically sends an OTP to the identifier and the form transitions to an OTP entry step:
Header text shows: “
OTP
 sent to: &lt;identifier&gt;”
A 6-digit OTP input field is displayed.
A countdown timer shows OTP expiry time (e.g., '4:59').
“Sign In” primary button and two secondary buttons: “
Change email/phone
” and “
Resend OTP
”.
The user enters the 6-digit OTP received via email or phone and clicks “
Sign In
”.
Figure 35: Login – OTP Entry Form
Step 4: Successful Login – Redirect to Dashboard
Upon successful credential verification, the system:
Validates the user's role (SUPER_ADMIN, ADMIN, or AUTHORITY).
Redirects Admin/Super Admin roles to the '/admin' dashboard.
Redirects Authority roles to the '/authority' dashboard.
Displays a green toast notification: 'Signed in successfully!'
Figure 36: Login – Successful Login (Role-based Redirect)
 
Step 5: Login with Google Account
As an alternative, the user can click the 'Google' button below the form separator.
The system calls the Google OAuth initialization API to generate the authorization URL.
The browser is redirected to Google's sign-in page (accounts.google.com).
The user selects their Google account and grants permission.
Google redirects back to /auth/callback, completing authentication and redirecting to the role-based dashboard.
Figure 37: Login – Google OAuth Login Flow
3.2.1.2 Forgot and Reset Password
Step 1: Initiate Forgot Password from the Login Form
On the Login screen (identifier step or password step), the user clicks the 'Forgot password?' link.
The system requires the identifier field to contain a value before initiating forgot password.
If the identifier field is empty, a warning is shown: 'Please enter email or phone number.'
Figure 38: Forgot Password – Trigger Link Location
Step 2: OTP Sent for Password Reset
With a valid identifier entered, the system calls the OTP send API and transitions the form to OTP verification mode (FORGOT_PASSWORD mode).
A success toast is displayed: 'Password reset OTP has been sent!'
Figure 39: Forgot Password – OTP Sent Confirmation
Step 3: Enter and Verify OTP
The user retrieves the 6-digit OTP from their email or phone.
The user types the OTP into the input field and clicks 'Verify OTP'.
If the OTP is fewer than 6 digits: yellow toast 'OTP must be 6 digits.'
If the OTP has expired, the 'Resend OTP' button becomes clickable to request a new code.
Figure 40: Forgot Password – OTP Input Interaction
Step 4: Set a New Password
Upon successful OTP verification in FORGOT_PASSWORD mode, the system logs the user in and automatically opens the 'Set a new password' modal over the dashboard.
Inside the dialog, the user enters:
New Password – must satisfy all five security requirements.
Confirm Password – must match the new password exactly.
Requirements are shown as a real-time checklist:
At least 8 characters
Contains uppercase (A-Z)
Contains lowercase (a-z)
Contains a number (0-9)
Contains a special character (!@#$...)
A password match indicator also appears when the user types in the Confirm Password field.
Figure 41: Forgot Password – Set New Password Modal
 
Step 5: Confirm Reset and Log In Normally
After the user clicks 'Set password' and the API confirms success:
Green toast: 'Password reset successful!'
The modal closes automatically.
The user is fully logged in and can use the system normally.
For future logins, the user signs in with their email and the newly set password (password-based flow).
 
Figure 42: Forgot Password – Password Reset Successful

3.2.4.1 View and Search Stations
Step 1: Navigate to the Station Management Page
After logging in, click on &quot;Stations&quot; in the left-hand sidebar of the Admin Dashboard.
The main area displays a table listing all monitoring stations registered in the system.
Figure 70: Station Management
Step 2: View Station Table
Each row in the table represents one monitoring station with the following information:
Code
 - The unique identifier code of the station (e.g., ST_DN_DRAGON_01). Used to quickly reference a station in the system.
Name
 - The full display name of the station (e.g., Dragon Bridge Station).
Road
 - The name of the road or area where the station is located.
Direction
 - The water flow direction relative to the station location:
Upstream
 - The station monitors water flowing toward the area.
Downstream
 - The station monitors water flowing away from the area.
Road Section
 - The station is placed at a specific road section.
Status - 
The current operating status of the station, shown as a colored badge:
Active (Green)
 - The station is running normally and sending data.
Maintenance (Yellow)
 - The station is temporarily offline for maintenance work.
Offline (Red)
 - The station is not responding or has stopped sending data.
Warn (Warning Threshold)
 - The water level (in meters) at which a Warning alert is triggered.
Critical (Critical Threshold)
 - The water level (in meters) at which a Critical alert is triggered.
Figure 71: View Station Table
Step 3: Search and Filter Stations
The toolbar above the table provides tools to quickly find a specific station:
Search by Name 
- Type part of the station name in the search box. The table filters results automatically as you type.
Status filter 
- Click the &quot;Status&quot; dropdown to show only stations with a specific status. You can select multiple statuses at the same time (e.g., show both Active and Maintenance stations at once).

3.2.4.2 Add a New Station
Step 1: Open the Add Station Form
On the Station Management page, click the &quot;+ Add Station&quot; button at the top-right of the toolbar.
A dialog box titled &quot;Create New Station&quot; will appear on the screen.
Figure 74: Add Station Button
      
Figure 75: Add Station Form
Step 2: Fill in Basic Information
The form is divided into several sections. Start with the basic details (fields marked with * are required):
Station Code * 
- Enter a unique code to identify this station. Use a consistent naming pattern (e.g., ST_DN_DRAGON_01 for Station - Da Nang - Dragon Bridge - Unit 01). Must be at least 2 characters.
Station Name * 
- Enter a descriptive name for the station (e.g., Dragon Bridge Station). Must be at least 2 characters.
Status * 
- Select the station's current operating state from the dropdown:
Active
 - The station is installed and operational.
Offline
 - The station is not currently sending data.
 Maintenance
 - The station is undergoing maintenance.
Road Name
 - Enter the name of the road or street where the station is placed (e.g., 2 Thang 9 Street).
Figure 76: Fill in Basic Information
Step 3: Add Location Details
Provide more information about where the station is physically located:
Location Description
 - Write a short description of the installation spot (e.g., &quot;Located on the west side of Dragon Bridge, near the riverbank&quot;). Maximum 500 characters.
Direction
 - Describe the water flow direction at this station (e.g., upstream, downstream, or road section).
Installed At
 - Enter the date and time when the station was physically installed. Use the standard date-time format shown in the placeholder.
Latitude
 - Enter the geographic latitude coordinate of the station (e.g., 16.061153). Must be between -90 and 90.
Longitude
 - Enter the geographic longitude coordinate of the station (e.g., 108.221589). Must be between -180 and 180.
Note: 
Latitude and Longitude are used to show the station on the map. If you do not know the exact coordinates, you can look them up using Google Maps.
Figure 77: Add Location Details
  
Step 4: Set Alert Thresholds
Alert thresholds define the water levels that trigger flood warnings for this station:
Threshold Warning
 - Set the water level (in meters) at which a Warning alert is sent (e.g., 0.5). When the measured water level reaches this value, the system will notify relevant users.
Threshold Critical
 - Set the water level (in meters) at which a Critical alert is sent (e.g., 1.2). This represents a more serious flooding condition that requires urgent attention.
Note: 
The Critical threshold should always be set higher than the Warning threshold to ensure alerts are triggered in the correct order.
